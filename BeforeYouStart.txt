## 2. Architecture in the Development Process

Architecture is not the first step in software development.

- Understanding when architecture begins is crucial.
- Architecture typically begins after requirements have been gathered and during solution analysis.
- It bridges the gap between understanding the problem and implementing the solution.
- Architectural decisions are made before detailed design and implementation.
- Good architecture considers the entire lifecycle, including eventual retirement.

**Critical Understanding:** Architecture begins after you understand what you are building (requirements) but before you decide exactly how to build it (detailed design).

## 4. Software Architecture Layers

Software is often separated into layers. The following is a common schema:

- Application Layer
- Domain Layer
- Generic Infrastructure
- Off-the-Shelf / Commercial Products
- Platform Layer

- What is the layer responsible for?
- How is layering accomplished?
- *"While a company's competitor will usually have a similar Domain Layer, the value of its IP is primarily found in the Generic Infrastructure Layer."* Explain.
- How does the Generic Infrastructure provide a competitive edge for the Application Layer?
- You are writing a CRM application. For each layer, describe several elements of the system that belong in that layer.
- What advantages are there to layering software in this way?
- In a newer version of your CRM you find elements of the software migrating between layers. Explain.
